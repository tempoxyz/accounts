# `wallet_authorizeAccessKey`

Authorizes an access key with an expiry, spending limits, and optional call scopes for delegated transaction signing.

## Request

```ts
type Request = {
  method: 'wallet_authorizeAccessKey'
  params: [{
    /** Address of the key (alternative to `publicKey`). */
    address?: Address
    /**
     * Chain ID to scope the authorization to.
     * Hex-encoded (`0x...`) on the wire, decoded to `bigint`.
     */
    chainId?: bigint
    /** Unix timestamp (seconds) when the key expires. */
    expiry: number
    /** Funding policy ID or inline permissions. */
    fundingPolicy?: true | Hex | {
      admins?: readonly Address[]
      rules: {
        maxSlippageBps: number
        sources: Record<Address, readonly { target: Address; data: Hex }[]>
      }
    }
    /** Key type. */
    keyType?: 'secp256k1' | 'p256' | 'webAuthn'
    /** TIP-20 spending limits. */
    limits?: {
      /** Token contract address. */
      token: Address
      /** Spending cap. Hex-encoded (`0x...`) on the wire, decoded to `bigint`. */
      limit: bigint
      /** Window length in seconds. Omit for an absolute (non-resetting) cap. */
      period?: number
    }[]
    /** Public key to authorize. */
    publicKey?: Hex
    /** Per-target call scopes. The key may only call these targets. */
    scopes?: {
      /** Target contract address the key may call. */
      address: Address
      /** Function selector (4-byte `0x...`) or human-readable signature. */
      selector?: Hex | string
      /** Allowed call recipients (e.g. `transfer(to, ...)`). */
      recipients?: Address[]
    }[]
    /** Optional funding prompt to show after approval. */
    showDeposit?: ShowDeposit
  }]
}

type ShowDeposit = boolean | {
  /** Human-readable amount to pre-fill (e.g. `"50"`). */
  amount?: string
  /** Display name shown in the deposit UI. */
  displayName?: string
  /** Token symbol or contract address to pre-fill. */
  token?: string | Address
}
```

Tempo Wallet-hosted approval pages require at least one `limits` entry and one `scopes` entry. Use the `address` field on each scope for the target contract; malformed scope entries are rejected before approval.

Set `showDeposit` to `true` or funding hints to show the optional deposit picker before the wallet returns the authorization result.

## Response

```ts
type Response = {
  /** The signed authorization payload. */
  keyAuthorization: KeyAuthorization
  /** Root account address that issued the authorization. */
  rootAddress: Address
}

type KeyAuthorization = {
  /** Address of the access key. */
  address: Address
  /** Chain ID the authorization is scoped to. Hex on the wire. */
  chainId: bigint
  /** Unix timestamp (seconds) when the authorization expires. May be `null`. */
  expiry: number | null | undefined
  /** Address derived from the key. */
  keyId: Address
  /** Key type. */
  keyType: 'secp256k1' | 'p256' | 'webAuthn'
  /** Signed spending limits, if any. */
  limits?: readonly {
    token: Address
    limit: bigint
    period?: number
  }[]
  /** Signed policy ID or inline policy with explicit admins. */
  fundingPolicy?: Hex | { admins: readonly Address[]; rules: {
    maxSlippageBps: number
    sources: Record<Address, readonly { target: Address; data: Hex }[]>
  } }
  /** Signature envelope from the root account. */
  signature: SignatureEnvelope
}
```

## Example

```ts
import { Expiry } from 'accounts'

const result = await provider.request({
  method: 'wallet_authorizeAccessKey',
  params: [
    {
      expiry: Expiry.days(1),
      limits: [
        { token: '0x20c0000000000000000000000000000000000001', limit: '0x5F5E100' },
      ],
      scopes: [{ address: '0x20c0000000000000000000000000000000000001' }],
      showDeposit: { amount: '50', token: 'USDC' },
    },
  ],
})
```

## Funding policies

With a local signing adapter, pass `fundingPolicy` to this method or to `wallet_connect.capabilities.authorizeAccessKey`. An existing policy ID is a nonzero `uint64`, encoded as hex over RPC. Inline policies commit the complete `rules` and `admins` in the authorization signature.

Set `fundingPolicy: true` to select the funding handler's default policy. The chain transport must support `eth_fillKeyAuthorization` and have an existing default policy configured. Accounts resolves and validates the policy ID before requesting a signature. Resolution failures stop authorization. The dialog adapter does not support funding-policy requests.

For inline policies, omitting `admins` defaults to `[rootAccount.address]`, using the account that authorizes the key. Explicit admins override this default. An empty admin list is invalid. Returned signed authorizations always contain explicit admins.

```ts
const { keyAuthorization, rootAddress } = await provider.request({
  method: 'wallet_authorizeAccessKey',
  params: [{
    address: key.address,
    keyType: 'p256',
    expiry,
    limits,
    fundingPolicy: { rules },
  }],
})
```

The app can keep its WebCrypto key and install the returned authorization in its Viem `keyAuthorizationManager`. Signing stays inside the Accounts adapter, including when the root account is already connected.

With the WebAuthn adapter, `fundingPolicy: true` and omitted admins require discovering the authenticated root before preparing the authorization. Login therefore requires a second assertion, including when a credential ID is cached. Explicit admins and existing policy IDs retain the combined login assertion. Registration resolves the created root before signing.

Configured authorization requests containing a funding policy request fresh approval instead of reusing a stored key whose current policy cannot be confirmed.
