# Privy

Use a custom adapter when Privy owns authentication or wallet state and the app still wants to use Tempo account features through the Accounts SDK.

## Integration shape

Privy should remain the system of record for the user session or wallet state it owns. The custom adapter translates Accounts SDK requests into the Privy-backed signing path and maps the result back into provider responses.

Target workspace for a future runnable example: `examples/enterprise-privy/`.

## Integration Checklist

- Define which Privy session proves user intent.
- Define where signing happens.
- Define which UI surfaces Privy owns and which surfaces the app owns.
- Map Privy errors into Accounts SDK provider errors.
- Run the connect and payment guides through the adapter.

## Review gates

- Supported Privy wallet model is documented.
- Privy-specific dependencies do not leak into consumers that are not using Privy.
- Account creation, approval, denial, recovery, and support states are owned by either Privy or the app.
- Security review confirms signer access cannot bypass the intended Privy session.
