# Errors [An app catches each refusal of Tempo ID, and branches on its reason.]

## Overview

Each call throws <SourceLink name="RequestError" path="src/Accounts.ts">`Accounts.RequestError`</SourceLink> when Tempo ID refuses a request. Its <SourceLink name="RequestError.reason" path="src/Accounts.ts">`reason`</SourceLink> is the refusal's stable name, its <SourceLink name="RequestError.code" path="src/Accounts.ts">`code`</SourceLink> the OAuth error code, and its message the fault and the fix.

The demo reads the user of an [access token](/docs/guides/api-authentication/authenticate-requests) that Tempo ID did not issue, and shows the error. The read needs no sign-in, and changes nothing.

### Catch the error

The handler throws again each error that is not an <SourceLink name="RequestError" path="src/Accounts.ts">`Accounts.RequestError`</SourceLink>, such as <SourceLink name="SignedOutError" path="src/Accounts.ts">`Accounts.SignedOutError`</SourceLink> without a session. import { Accounts } from 'accounts'

```ts [main.ts]
export async function readConnection() {
  try {
    const { accessKeys } = await accounts.connection.get()
    return `The app holds ${accessKeys.length} access keys.`
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error // [!code hl]
    return error.message // [!code hl]
  }
}
```

### Branch on the reason

A message's wording may change, and a <SourceLink name="RequestError.reason" path="src/Accounts.ts">`reason`</SourceLink> does not. `invalid_token` refuses an expired or revoked access token, or another app's. [Reasons](#reasons) lists each reason.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function readConnection() {
  try {
    const { accessKeys } = await accounts.connection.get()
    return `The app holds ${accessKeys.length} access keys.`
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error
    if (error.reason === 'invalid_token') return 'Sign in again.' // [!code ++]
    return error.message
  }
}
```

### Retry a temporary failure

A rate limit and a failed service have different reasons, and share the code `temporarily_unavailable`. A branch on the <SourceLink name="RequestError.code" path="src/Accounts.ts">`code`</SourceLink> handles both.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function readConnection() {
  try {
    const { accessKeys } = await accounts.connection.get()
    return `The app holds ${accessKeys.length} access keys.`
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error
    if (error.reason === 'invalid_token') return 'Sign in again.'
    if (error.code === 'temporarily_unavailable') return 'Try again later.' // [!code ++]
    return error.message
  }
}
```

## Use cases

Each use case reads one property of <SourceLink name="RequestError" path="src/Accounts.ts">`Accounts.RequestError`</SourceLink>, or catches another error class of the package.

### Handle a refusal without a reason

Tempo ID's OAuth endpoints return no <SourceLink name="RequestError.reason" path="src/Accounts.ts">`reason`</SourceLink>, so the app branches on the <SourceLink name="RequestError.code" path="src/Accounts.ts">`code`</SourceLink>. A refresh with a revoked or expired refresh token fails with `invalid_grant`.

<SourceLink name="userInfo" path="src/plugins/tokens.ts">`tokens.userInfo`</SourceLink> sets the reason `invalid_token` itself, for each access token that Tempo ID refuses.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function refresh() {
  try {
    await accounts.session.refresh()
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error
    if (error.code === 'invalid_grant') console.log('Sign in again.') // [!code hl]
  }
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'

export const accounts = Accounts.create({ chain: 'testnet' })
```

### Detect a refusal before a request

The package refuses some options, such as a past <SourceLink name="expiry" path="src/Permissions.ts">`expiry`</SourceLink>, before any request. The error holds Tempo ID's reason, and <SourceLink name="RequestError.status" path="src/Accounts.ts">`status`</SourceLink> 0.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'

  try {
    await accounts.dialog.signIn({
      accessKey: { expiry: 1, limits: [{ limit: '100', token: 'ousd' }] },
    })
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error
    console.log(error.reason, error.status) // 'expiry_passed', 0
  }
}
```

### Show the field at fault

<SourceLink name="RequestError.field" path="src/Accounts.ts">`field`</SourceLink> names the request field at fault as a dotted path, such as the limit of an access key. A form shows the message beside that field.

```ts [main.ts]
import { Accounts } from 'accounts'

export function fieldError(error: Accounts.RequestError, name: string) {
  return error.field === name ? error.message : undefined // [!code hl]
}
```

### Wait out a rate limit

<SourceLink name="RequestError.meta" path="src/Accounts.ts">`meta`</SourceLink> holds the values that the refusal compared. For `rate_limited`, it holds the seconds to wait, if Tempo ID knows them.

```ts [main.ts]
import { Accounts } from 'accounts'

export function wait(error: Accounts.RequestError) {
  if (error.reason !== 'rate_limited') return undefined
  return Number(error.meta?.retryAfter ?? 60) // [!code hl]
}
```

### Link the explanation

<SourceLink name="RequestError.uri" path="src/Accounts.ts">`uri`</SourceLink> holds the link to Tempo ID's description of the error, as the [Reasons](#reasons) table shows. A support page or a log shows it beside the message.

```ts [main.ts]
import { Accounts } from 'accounts'

export function describe(error: Accounts.RequestError) {
  if (!error.uri) return error.message
  return `${error.message} See ${error.uri}.` // [!code hl]
}
```

### Restart a failed sign-in

A sign-in can fail after the user's code or passkey verified, such as when Tempo ID refuses the authorization. The error then has <SourceLink name="RequestError.signedIn" path="src/Accounts.ts">`signedIn`</SourceLink>, and the instance empties its session.

The emailed code verified already, so the app requests a new one. Without `signedIn`, the session stays as it was.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function signIn(email: string, code: string) {
  try {
    await accounts.email.signIn({ code, email })
  } catch (error) {
    if (!(error instanceof Accounts.RequestError)) throw error
    if (error.signedIn) await accounts.email.sendCode({ email }) // [!code hl]
    return error.message
  }
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { email } from 'accounts/plugins'

export const accounts = Accounts.create({
  chain: 'testnet',
  clientId: 'example-app',
  plugins: [email()],
})
```

### Ignore a closed dialog

A closed dialog is no refusal. <SourceLink name="signIn" path="src/plugins/dialog.ts">`dialog.signIn`</SourceLink> throws a `DOMException` named `AbortError` for it, and for a sign-in that a later one replaces. A closed passkey prompt is none either: <SourceLink name="signIn" path="src/plugins/passkey.ts">`passkey.signIn`</SourceLink>, <SourceLink name="register" path="src/plugins/passkey.ts">`passkey.register`</SourceLink>, and <SourceLink name="signIn" path="src/plugins/email.ts">`email.signIn`</SourceLink> with `link` throw an `Error` named `AbortError` for it, since React Native has no `DOMException`. The app checks the name alone. An authenticator that already holds one of the user's passkeys refuses a new one, so `passkey.register` throws an `Error` named `InvalidStateError`, and the app offers a sign-in with that passkey instead.

If another sign-in or a sign-out completes first, it throws <SourceLink name="SupersededError" path="src/Accounts.ts">`Accounts.SupersededError`</SourceLink>. The app ignores both.

:::code-group

```tsx [SignIn.tsx]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export function SignIn() {
  async function signIn() {
    try {
      await accounts.dialog.signIn()
    } catch (error) {
      // [!code hl:start]
      if (error instanceof Error && error.name === 'AbortError') return
      if (error instanceof Accounts.SupersededError) return
      // [!code hl:end]
      throw error
    }
  }

  return (
    <button onClick={signIn} type="button">
      Sign in with Tempo
    </button>
  )
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'

export const accounts = Accounts.create({ chain: 'testnet' })
```

### Send only when signed in

A transaction without a session throws <SourceLink name="SignedOutError" path="src/Accounts.ts">`Accounts.SignedOutError`</SourceLink>. If a refused refresh token ended the session, its `cause` holds that refusal.

A transaction from a session without an access key throws <SourceLink name="AccessKeyRequiredError" path="src/Accounts.ts">`Accounts.AccessKeyRequiredError`</SourceLink>. The app then signs the user in with an [access key](/docs/guides/access-keys/authorize-access-keys).

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { parseUnits } from 'viem'
import { Addresses } from 'viem/tempo'
import { accounts } from './tempo.config.js'

export async function send() {
  try {
    await accounts.token.transferSync({
      amount: parseUnits('1', 6),
      to: '0x000000000000000000000000000000000000dEaD',
      token: Addresses.ousd,
    })
  } catch (error) {
    // [!code hl:start]
    if (error instanceof Accounts.SignedOutError) return 'Sign in to send.'
    if (error instanceof Accounts.AccessKeyRequiredError)
      return 'Sign in with an access key to send.'
    // [!code hl:end]
    throw error
  }
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { viem } from 'accounts/plugins'

export const accounts = Accounts.create({
  chain: 'testnet',
  plugins: [viem()],
})
```

### Handle an ended retry

If a transaction fails for its access key, its limit, or its balance, the <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin shows a screen that resolves it, then sends again. If the user closes the screen, the call throws <SourceLink name="RetryClosedError" path="src/plugins/viem.ts">`Plugins.viem.RetryClosedError`</SourceLink>.

If the sign-in for a new access key returns another account, the call throws <SourceLink name="RetryAccountError" path="src/plugins/viem.ts">`Plugins.viem.RetryAccountError`</SourceLink>. The app matches both by name.

:::code-group

```ts [main.ts]
import { parseUnits } from 'viem'
import { Addresses } from 'viem/tempo'
import { accounts } from './tempo.config.js'

export async function send() {
  try {
    await accounts.token.transferSync({
      amount: parseUnits('1', 6),
      to: '0x000000000000000000000000000000000000dEaD',
      token: Addresses.ousd,
    })
  } catch (error) {
    // [!code hl:start]
    const { name } = error as Error
    if (name === 'Plugins.viem.RetryClosedError') return 'The transaction did not send.'
    if (name === 'Plugins.viem.RetryAccountError') return 'Sign in with the same account.'
    // [!code hl:end]
    throw error
  }
}
```

```ts [tempo.config.ts]
import { viem } from 'accounts/plugins'

})
```

### Ignore a revoked access key

<SourceLink name="accessKey" path="src/plugins/viem.ts">`accessKey.revokeSync`</SourceLink> throws <SourceLink name="RevokedError" path="src/Accounts.ts">`Accounts.RevokedError`</SourceLink> if the chain holds the access key revoked already. A sign-out ignores it, since the access key signs nothing.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function signOut() {
  const { session } = accounts.session.status.get()
  const accessKey = session?.accessKey?.keyAuthorization.keyId

  try {
    if (accessKey) await accounts.accessKey.revokeSync({ accessKey })
  } catch (error) {
    if (!(error instanceof Accounts.RevokedError)) throw error // [!code hl]
  }
  await accounts.signOut()
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { viem } from 'accounts/plugins'

  chain: 'testnet',
  plugins: [viem()],
})
```

### Catch the errors of a guest session

A [guest session](/docs/guides/guest-checkout) holds no Tempo ID tokens. A call that reads Tempo ID as the user, such as `account.get`, throws <SourceLink name="GuestSessionError" path="src/Accounts.ts">`Accounts.GuestSessionError`</SourceLink>. An MPP payment without a cap throws <SourceLink name="MaxAmountRequiredError" path="src/mpp/index.ts">`mpp.MaxAmountRequiredError`</SourceLink> or <SourceLink name="MaxDepositRequiredError" path="src/mpp/index.ts">`mpp.MaxDepositRequiredError`</SourceLink>, and a malformed `maxDeposit` <SourceLink name="MaxDepositInvalidError" path="src/mpp/index.ts">`mpp.MaxDepositInvalidError`</SourceLink>. Outside a page, a guest payment whose outcome Tempo ID does not confirm throws <SourceLink name="PendingError" path="src/actions/guest.ts">`Actions.guest.PendingError`</SourceLink>, which names the checkout in `checkout`. The store keeps nothing of it, and a later `pay` of the same payment opens a new checkout, which can pay again. Confirm the outcome of the checkout before paying again.

:::code-group

```ts [main.ts]
import { Accounts } from 'accounts'
import { accounts } from './tempo.config.js'

export async function readAccount() {
  try {
    return await accounts.account.get()
  } catch (error) {
    // A guest session has no Tempo ID user, so the app reads its address instead.
    if (error instanceof Accounts.GuestSessionError) return undefined // [!code hl]
    throw error
  }
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'

export const accounts = Accounts.create({
  chain: 'testnet',
  guest: true,
})
```
