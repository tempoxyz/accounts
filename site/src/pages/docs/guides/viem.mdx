# Viem [An app sends transactions and signs messages on Tempo with a Viem client whose account follows the session.]

## Overview

The <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin adds a [Viem](https://viem.sh) client to the instance. A sign-in sets the client's account to the user's Tempo Account, and a sign-out empties it, so no action names an account.

The [session](/docs/guides/user-session)'s [access key](/docs/guides/access-keys) signs each transaction and message with no prompt. The instance also holds each action of the client, so an app calls them on the instance itself.

The demo signs a user in, and sends 1 OUSD on Tempo testnet. It then signs a message with the access key, and verifies the signature.

### Send a transaction

Viem's [`token.transfer`](https://viem.sh/tempo/actions/token.transfer) action sends 1 OUSD, and the access key signs it. The sync form waits for the receipt.

:::code-group

```tsx [Send.tsx]
import { parseUnits } from 'viem'
import { Addresses } from 'viem/tempo'
import { accounts } from './tempo.config.js'

export function Send() {
  return (
    <button
      onClick={async () => {
        // [!code hl:start]
        const { receipt } = await accounts.viem.token.transferSync({
          amount: parseUnits('1', 6),
          to: '0x000000000000000000000000000000000000dEaD',
          token: Addresses.ousd,
        })
        // [!code hl:end]
        console.log(receipt.transactionHash)
      }}
      type="button"
    >

    </button>
  )
}
```

Viem's docs list the client's [Tempo](https://viem.sh/tempo/actions), [public](https://viem.sh/docs/actions/public/introduction), and [wallet](https://viem.sh/docs/actions/wallet/introduction) actions. The instance holds the same actions, so the call above also works without the client.

The chain lets the access key make only the calls of its scopes. With limits alone, it transfers each limited token, approves each limit's spenders, and opens and tops up TIP-1034 channels. Another call rejects with Viem's `AccessKeyCallNotAllowedError`.

## Use cases

Each use case calls an action of the client of the <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin, or sets one option of the plugin or of a call of its client.

### Send several calls

```tsx [SendBoth.tsx]
              amount: parseUnits('2', 6),
              to: '0x000000000000000000000000000000000000bEEF',
              token: Addresses.ousd,
```

### Retry a refused transaction

On a page, the client retries a transaction that the node refuses for these reasons. Tempo ID's screen shows first, then the transaction sends again.

| Kind        | Refusal                                                             | Screen       |
| ----------- | ------------------------------------------------------------------- | ------------ |
| `accessKey` | The chain does not hold the access key, or it expired or is revoked | Sign-in      |
| `balance`   | The Tempo Account holds too little of the token or of the fee token | Deposit page |
| `limit`     | The access key spent its limit                                      | Sign-in      |

If the user closes the screen, the action rejects with <SourceLink name="RetryClosedError" path="src/plugins/viem.ts">`Plugins.viem.RetryClosedError`</SourceLink>, and sends nothing.

:::code-group

```tsx [Send.tsx]
import { parseUnits } from 'viem'
import { Addresses } from 'viem/tempo'
import { accounts } from './tempo.config.js'

export function Send() {
  return (
    <button
      onClick={async () => {
        try {
          await accounts.token.transferSync({
            amount: parseUnits('1', 6),
            to: '0x000000000000000000000000000000000000dEaD',
            token: Addresses.ousd,
          })
        } catch (error) {
          if ((error as Error).name !== 'Plugins.viem.RetryClosedError') // [!code hl]
            throw error
          console.log('The transaction did not send.')
        }
      }}
      type="button"
    >
      Send 1 OUSD
    </button>
  )
}
```

### Relay through another origin

Each request to a relay route at the app's origin carries the session's access token, so the route can verify its caller. With <SourceLink name="viem.relay.credentials" path="src/plugins/viem.ts">`credentials: 'include'`</SourceLink>, a route on another origin, such as the app's API, also receives it.

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { viem } from 'accounts/plugins'
import { react } from 'accounts/react'

export const accounts = Accounts.create({
  chain: 'testnet',
  plugins: [
    react(),
    viem({
      // [!code hl:start]
      relay: { credentials: 'include', url: 'https://api.example.com/relay' },
      // [!code hl:end]
    }),
  ],
})
```

### Sign a message as the Tempo Account

The access key signs a keychain envelope for the Tempo Account, with no prompt. A verifier accepts it only after the chain holds the access key, such as after the [walkthrough's](#send-a-transaction) first transaction.

:::code-group

```tsx [Sign.tsx]
import { accounts } from './tempo.config.js'

const message = 'Hello from Tempo ID'

export function Sign() {
  return (
    <button
      onClick={async () => {
        // [!code hl:start]
        const signature = await accounts.signMessage({ message })

        const valid = await accounts.verifyMessage({
          accessToken: await accounts.session.accessToken(),
          address: accounts.viem.account.address,
          message,
          signature,
        })
        // [!code hl:end]
        console.log(valid)
      }}
      type="button"
    >
      Sign a message
    </button>
  )
}
```


:::

The verification counts the signature only if the session's [access token](/docs/guides/api-authentication/authenticate-requests) names the access key that signed. Without an access token, it returns `false`, and an access token that does not verify throws <SourceLink name="InvalidError" path="src/AccessToken.ts">`AccessToken.InvalidError`</SourceLink>.

:::warning
A Viem client without the package verifies with the allowAccessKey mode of [`verifyMessage`](https://viem.sh/docs/actions/public/verifyMessage). That mode accepts each access key that the chain holds for the Tempo Account, also another app's access key.
:::

### Approve a shared account's transaction

A configurable account with several owners sends once enough of them approve, as Viem's [coordinated signing](https://viem.sh/tempo/guides/configurable-accounts/send#coordinated-signing) describes. If the user's passkey is one of its owners, <SourceLink name="sendTransactionSync" path="src/plugins/viem.ts">`sendTransactionSync`</SourceLink> approves without an `owner`: with the account's transaction, or with the operation `hash` alone. Coordination needs the plugin's `relay`, and the passkey signs only on the page of a first-party app with the `tempo-id:sign` scope.

:::code-group

```tsx [Approve.tsx]
import { Account } from 'viem/tempo'
import { accounts } from './tempo.config.js'

// A 2-of-2 account of the user's passkey and the app's cosigner.
const account = Account.fromConfig('0x7a3f2c1d5e8b9a0f4c6d3e2b1a0f9e8d7c6b5a49')

export function Approve(props: Approve.Props) {
  return (
    <button
      onClick={async () => {
        // [!code hl:start]
        const receipt = props.hash
          ? await accounts.viem.sendTransactionSync({ hash: props.hash })
          : await accounts.viem.sendTransactionSync({
              account,
              calls: [{ to: '0x1f9090aaE28b8a3dCeaDf281B0F12828e676c326', value: 0n }],
            })
        // [!code hl:end]
        console.log(receipt.status, receipt.operation)
      }}
      type="button"
    >
      Approve
    </button>
  )
}

export declare namespace Approve {
  type Props = {
    /** The operation hash of a transaction that another owner sent. */
    hash?: `0x${string}` | undefined
  }
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { viem } from 'accounts/plugins'
import { react } from 'accounts/react'

export const accounts = Accounts.create({
  chain: 'testnet',
```


### Check the registration

Viem's [`accessKey.getMetadata`](https://viem.sh/tempo/actions/accessKey.getMetadata) reads the access key from the chain. The chain returns the zero address for an access key that it does not hold, and marks a revoked one.

:::code-group

```tsx [Registration.tsx]
import { isAddressEqual } from 'viem'
import { accounts } from './tempo.config.js'

export function Registration() {
  const { session } = accounts.useSession()

  if (!session?.accessKey) return null

  const { account, keyAuthorization } = session.accessKey

  return (
    <button
      onClick={async () => {
        // [!code hl:start]
        const metadata = await accounts.accessKey.getMetadata({
          accessKey: keyAuthorization.keyId,
          account,
        })
        // [!code hl:end]
        const registered =
          !metadata.isRevoked &&
          isAddressEqual(metadata.address, keyAuthorization.keyId)
        console.log(registered)
      }}
      type="button"
```

### Send with a server's session

With the <SourceLink name="backend" path="src/plugins/backend.ts">`backend`</SourceLink> plugin, a server holds the session, and the <SourceLink name="viem.chainId.session" path="src/plugins/viem.ts">`session`</SourceLink> of a client call signs with its access key. A server shows no screen, so a refused transaction rejects with its error.

```ts [server.ts]
import { Accounts, Store } from 'accounts'
import { backend, viem } from 'accounts/plugins'
import { Hono } from 'hono'
import { parseUnits } from 'viem'
import { Addresses } from 'viem/tempo'

const accounts = Accounts.create({
  accessKey: () => ({
    expiry: '1d',
    limits: [{ limit: '10', token: 'ousd' }],
  }),
  chain: 'testnet',
  clientId: process.env.APP_URL,
  plugins: [backend({ store: Store.memory() }), viem()],
})

const app = new Hono()

// The sign-in routes of the `backend` plugin.
app.all('/api/*', (c) => accounts.handler.fetch(c.req.raw))

app.post('/send', async (c) => {
  const session = await accounts.session.get(c.req.raw)
  if (session?.method !== 'tempo-id') return c.body(null, 401)

  const { receipt } = await accounts.viem({ session }).token.transferSync({ // [!code hl]
    amount: parseUnits('1', 6),
    to: '0x000000000000000000000000000000000000dEaD',
    token: Addresses.ousd,
  })
  return c.json({ hash: receipt.transactionHash })
})

export default app
```

:::note

<SourceLink name="create" path="src/stores/Memory.ts">`Store.memory`</SourceLink> keeps the sessions in the process, so a restart loses them. In production, use a store that each replica shares, such as <SourceLink name="create" path="src/stores/Postgres.ts">`Store.postgres`</SourceLink> or <SourceLink name="create" path="src/stores/Redis.ts">`Store.redis`</SourceLink>.
:::

### Use another Tempo ID or chain

The guides use Tempo ID's own origin, and Tempo testnet with its own RPC. Three options change them.

| Option                                                                                                                                                                                         | Sets                                                                 | Default                              |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- | ------------------------------------ |
| <SourceLink name="from.url" path="src/Accounts.ts">`url`</SourceLink>                                                                                                                          | The origin of Tempo ID, such as a self-hosted or a local deployment  | `https://id.tempo.xyz`               |
| <SourceLink name="from.chain" path="src/Accounts.ts">`chain`</SourceLink>                                                                                                                      | `'mainnet'`, `'testnet'`, or the ID of another chain, such as `1337` | `'mainnet'`                          |
| <SourceLink name="viem.chain" path="src/plugins/viem.ts">`viem({ chain })`</SourceLink>, <SourceLink name="viem.relay.transport" path="src/plugins/viem.ts">`viem({ transport })`</SourceLink> | The Viem chain of that ID, and the transport of its RPC              | Tempo's chain of the ID, and its RPC |

The instance's chain is an ID, not a Viem chain. Viem's chain of a local node uses an RPC on port 8545, so a node at another URL needs a transport.

The <SourceLink name="mpp" path="src/mpp/index.ts">`mpp`</SourceLink> plugin reads the chain and the transport of the <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin. Token symbols such as OUSD resolve on mainnet, testnet, devnet, and a local node.

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { viem } from 'accounts/plugins'
import { http } from 'viem'
import { tempoLocalnet } from 'viem/tempo/chains'

export const accounts = Accounts.create({
  chain: tempoLocalnet.id,
  plugins: [
    viem({ chain: tempoLocalnet, transport: http('http://localhost:9545/1') }),
  ],
  url: 'http://localhost:8787',
})
```
