# Migration from v0 [Replace each API of version 0 of the package with its API of version 1.]

Version 0 of `accounts` connects an app to Tempo Wallet through an EIP-1193 provider. The app sends RPC methods, such as `wallet_connect` and `eth_sendTransaction`, and Tempo Wallet's dialog signs each call that no access key covers.

Version 1 is the SDK of Tempo ID, an OAuth 2.0 and OpenID Connect provider. A sign-in returns a [session](/docs/guides/user-session) with the user, the tokens, and an [access key](/docs/guides/access-keys) that signs each transaction within the limits that the user approved. <SourceLink name="create" path="src/Accounts.ts">`Accounts.create`</SourceLink> returns an instance in place of a provider, and plugins add its members.

[Notable changes](#notable-changes) covers what affects most apps, and [Quick reference](#quick-reference) lists each API of version 0. In each diff, removed lines are code of version 0, and added lines code of version 1.

## Installation

```

```

## Notable changes

### Instance creation

<SourceLink name="create" path="src/Accounts.ts">`Accounts.create`</SourceLink> replaces `Provider.create`, and <SourceLink name="from.chain" path="src/Accounts.ts">`chain`</SourceLink> replaces `testnet`. A web app needs no registration, since the page's origin is its client ID. See [Instance](#instance).

```ts [tempo.config.ts]
import { Provider, tempoWallet } from 'accounts' // [!code --]
import { Accounts } from 'accounts' // [!code ++]
import { dialog, viem } from 'accounts/plugins' // [!code ++]

const provider = Provider.create({ // [!code --]
  adapter: tempoWallet(), // [!code --]
  testnet: true, // [!code --]
}) // [!code --]
export const accounts = Accounts.create({ // [!code ++]
  chain: 'testnet', // [!code ++]
  plugins: [dialog(), viem()], // [!code ++]
}) // [!code ++]
```

### Sign-in plugins

A sign-in plugin replaces each adapter, and its <SourceLink name="signIn" path="src/plugins/dialog.ts">`signIn`</SourceLink> replaces `wallet_connect`. <SourceLink name="dialog" path="src/plugins/dialog.ts">`dialog`</SourceLink> shows Tempo ID's sign-in over the page, as `tempoWallet` showed Tempo Wallet. See [Sign-in](#sign-in).

:::code-group

```ts [signIn.ts]
import { accounts } from './tempo.config.js' // [!code ++]

export async function signIn() {
  const result = await provider.request({ method: 'wallet_connect' }) // [!code --]
  const address = result.accounts[0]?.address // [!code --]
  const session = await accounts.dialog.signIn() // [!code ++]
  const address = session.accessKey?.account // [!code ++]
  return address
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { dialog, viem } from 'accounts/plugins'

export const accounts = Accounts.create({
  chain: 'testnet',
  plugins: [dialog(), viem()],
})
```

:::

### Sessions

One session, which <SourceLink name="session" path="src/Accounts.ts">`accounts.session`</SourceLink> reads, replaces the accounts of `provider.store`. An instance does not read version 0's stored state, so each user signs in once after the upgrade. See [Session and storage](#session-and-storage).

:::code-group

```ts [session.ts]
import { accounts } from './tempo.config.js' // [!code ++]

export async function watch(render: (address: string | undefined) => void) {
  await provider.ready() // [!code --]
  const [address] = await provider.request({ method: 'eth_accounts' }) // [!code --]
  const session = await accounts.session.get() // [!code ++]
  const address = session?.accessKey?.account // [!code ++]
  render(address)

  provider.on('accountsChanged', ([address]) => render(address)) // [!code --]
  accounts.session.subscribe((session) => render(session?.accessKey?.account)) // [!code ++]
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts'
import { dialog, viem } from 'accounts/plugins'

export const accounts = Accounts.create({
  chain: 'testnet',
  plugins: [dialog(), viem()],
})
```

### Access key requests

The app requests an access key at each sign-in with the <SourceLink name="create.accessKey" path="src/Accounts.ts">`accessKey`</SourceLink> option, which replaces `accessKey.authorize`. It takes a duration, a decimal limit, and a token symbol. See [Access keys](#access-keys).

```ts [tempo.config.ts]
import { Expiry } from 'accounts' // [!code --]
import { Addresses } from 'viem/tempo' // [!code --]
import { Accounts } from 'accounts' // [!code ++]
import { dialog, viem } from 'accounts/plugins' // [!code ++]

const provider = Provider.create({ // [!code --]
  accessKey: { // [!code --]
    authorize: { // [!code --]
      expiry: Expiry.days(1), // [!code --]
      limits: [{ limit: 100_000_000n, token: Addresses.ousd }], // [!code --]
    }, // [!code --]
  }, // [!code --]
}) // [!code --]
export const accounts = Accounts.create({ // [!code ++]
  accessKey: () => ({ // [!code ++]
    expiry: '1d', // [!code ++]
    limits: [{ limit: '100', token: 'ousd' }], // [!code ++]
  }), // [!code ++]
  chain: 'testnet', // [!code ++]
  plugins: [dialog(), viem()], // [!code ++]
}) // [!code ++]
```

### Instance methods

A method of the instance replaces each RPC method. <SourceLink name="pay" path="src/Accounts.ts">`accounts.pay`</SourceLink> replaces `wallet_transfer`, with the same decimal amount, and the access key signs with no prompt. The <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin's actions take Viem's values, such as an amount in base units. See [RPC methods](#rpc-methods).

:::code-group

```ts [send.ts]
import { Addresses } from 'viem/tempo'
import { accounts } from './tempo.config.js' // [!code ++]

const to = '0x000000000000000000000000000000000000dEaD'

export async function send() {
  await provider.request({ // [!code --]
    method: 'wallet_transfer', // [!code --]
    params: [{ amount: '1', to, token: Addresses.ousd }], // [!code --]
  }) // [!code --]
  const { transaction } = await accounts.pay({ // [!code ++]
    amount: '1', // [!code ++]
    to, // [!code ++]
    token: Addresses.ousd, // [!code ++]
  }) // [!code ++]
  return transaction // [!code ++]
}
```

### Wagmi connector

The <SourceLink name="tempoId" path="src/wagmi/index.ts">`tempoId`</SourceLink> connector of `accounts/wagmi` replaces `tempoWallet` of `wagmi/connectors`, and takes the options of <SourceLink name="create" path="src/Accounts.ts">`Accounts.create`</SourceLink>. The hooks of Viem's actions replace `Hooks.wallet`, which sends Tempo Wallet's RPC methods. See [Wagmi](#wagmi).

```ts
import { tempoId } from 'accounts/wagmi' // [!code ++]
import { createConfig, http } from 'wagmi'
import { tempoModerato } from 'wagmi/chains'
import { tempoWallet } from 'wagmi/connectors' // [!code --]

export const config = createConfig({
  chains: [tempoModerato],
  connectors: [tempoWallet()], // [!code --]
  connectors: [ // [!code ++]
    // The page's origin is a third-party client ID, whose connection needs an access key. // [!code ++]
    tempoId({ accessKey: { expiry: '1d', limits: [{ limit: '100', token: 'ousd' }] } }), // [!code ++]
  ], // [!code ++]
  transports: { [tempoModerato.id]: http() },
})
```

### Server plugins

One server instance replaces each `Handler` of `accounts/server`, and the <SourceLink name="backend" path="src/plugins/backend.ts">`backend`</SourceLink> plugin replaces `Handler.auth`. The backend holds the session and its access key, and the page holds only a cookie. See [Server](#server).

```ts [server.ts]
import { Handler, Kv } from 'accounts/server' // [!code --]
import { Accounts, Store } from 'accounts' // [!code ++]
import { backend } from 'accounts/plugins' // [!code ++]

const auth = Handler.auth({ path: '/api/auth', store: Kv.memory() }) // [!code --]
const accounts = Accounts.create({ // [!code ++]
  clientId: 'https://app.example', // [!code ++]
  plugins: [backend({ store: Store.memory() })], // [!code ++]
}) // [!code ++]

export default {
  fetch: (request: Request) => auth.fetch(request), // [!code --]
  fetch: (request: Request) => accounts.handler.fetch(request), // [!code ++]
}
```

### Fee relay

The <SourceLink name="relay" path="src/plugins/relay.ts">`relay`</SourceLink> plugin replaces `Handler.relay`, and the <SourceLink name="viem" path="src/plugins/viem.ts">`viem`</SourceLink> plugin's <SourceLink name="viem.relay" path="src/plugins/viem.ts">`relay`</SourceLink> option replaces `feePayer`. A relay is a JSON-RPC proxy whose fee payer co-signs each transaction.

Version 0's route checks no caller, and version 1's verifies each request's access token. See [Fee sponsorship](#fee-sponsorship).

```ts [tempo.config.ts]
import { Accounts } from 'accounts' // [!code ++]
import { dialog, viem } from 'accounts/plugins' // [!code ++]

const provider = Provider.create({ // [!code --]
  adapter: tempoWallet(), // [!code --]
  feePayer: '/api/relay', // [!code --]
}) // [!code --]
export const accounts = Accounts.create({ // [!code ++]
  chain: 'testnet', // [!code ++]
  plugins: [dialog(), viem({ relay: '/api/relay' })], // [!code ++]
}) // [!code ++]
```

### Removed adapters

Version 1 has no replacement for the adapters that hold an owner key in the app: `local`, `secp256k1`, `webAuthn`, `turnkey`, and `privy`. The app holds only an access key, never a Tempo Account's owner key. See [Removed APIs](#removed-apis).

### Removed surface

The root entry exports no EIP-1193 provider and no RPC schema, and only the wagmi connector's <SourceLink name="tempoId.getProvider" path="src/wagmi/index.ts">`getProvider`</SourceLink> returns a provider. Version 1 has no wallet-side module, such as `Remote` and `Messenger`, since Tempo ID is the only wallet side, and no handler for a flow that Tempo ID serves. See [Removed APIs](#removed-apis).

| Adapter       | Options                                           |
| ------------- | ------------------------------------------------- |
| `dialog`      | `dialog`, `host`, `icon`, `name`, `rdns`, `theme` |

Tempo ID's approval page names the app: the host for an origin client ID, or the name of the app's [registration](https://github.com/tempoxyz/id/blob/main/docs/apps.md#registration).

import { accounts } from './tempo.config.js' // [!code ++]

export async function signIn(message: string) {
  const result = await provider.request({ // [!code --]
    method: 'wallet_connect', // [!code --]
    params: [{ capabilities: { personalSign: { message } } }], // [!code --]
  }) // [!code --]
  const signature = result.accounts[0]?.capabilities.signature // [!code --]
  const session = await accounts.dialog.signIn({ challenge: message }) // [!code ++]
  const signature = session.challengeSignature // [!code ++]
  return signature
}
```

    validate: (request) => request.to === allowed, // [!code --]
  }, // [!code --]
  path: '/api/relay', // [!code --]
}) // [!code --]
const accounts = Accounts.create({ // [!code ++]
  chain: 'testnet', // [!code ++]
  clientId: 'https://app.example', // [!code ++]
  plugins: [ // [!code ++]
    relay({ // [!code ++]
      plugins: [ // [!code ++]
        Relay.feePayer({ // [!code ++]
          account, // [!code ++]
          validate: (request) => request.to === allowed, // [!code ++]
        }), // [!code ++]
        Relay.autoSwap(), // [!code ++]
      ], // [!code ++]
    }), // [!code ++]
  ], // [!code ++]
}) // [!code ++]

const app = new Hono()

app.post('/api/relay', (c) => handler.fetch(c.req.raw)) // [!code --]
app.post('/api/relay', (c) => accounts.relay.fetch(c.req.raw)) // [!code ++]

export default app
```

With <SourceLink name="relay.verify" path="src/plugins/relay.ts">`verify: false`</SourceLink>, the route checks no caller, as in version 0. Use it only behind the app's own guard, such as a backend session.

### Stores

<SourceLink name="Store" path="src/Store.ts">`Store`</SourceLink> replaces `Kv` of `accounts/server`. The <SourceLink name="backend" path="src/plugins/backend.ts">`backend`</SourceLink> plugin's <SourceLink name="backend.store" path="src/plugins/backend.ts">`store`</SourceLink> holds each backend session.

## MPP

The <SourceLink name="mpp" path="src/mpp/index.ts">`mpp`</SourceLink> plugin of `accounts/mpp` replaces the `mpp` option. Version 0's option is on by default, and replaces the global `fetch`. Version 1 leaves the global `fetch`, and adds <SourceLink name="mpp" path="src/mpp/index.ts">`accounts.fetch`</SourceLink>, which pays each HTTP 402 challenge with the session's access key.

:::code-group

```ts [fortune.ts]
import { accounts } from './tempo.config.js' // [!code ++]

export async function fortune() {
  const response = await fetch('https://api.example.com/fortune') // [!code --]
  const response = await accounts.fetch('https://api.example.com/fortune') // [!code ++]
  return response.text()
}
```

```ts [tempo.config.ts]
import { Accounts } from 'accounts' // [!code ++]
import { mpp } from 'accounts/mpp' // [!code ++]
import { dialog, viem } from 'accounts/plugins' // [!code ++]

const provider = Provider.create({ mpp: true }) // [!code --]
export const accounts = Accounts.create({ // [!code ++]
  accessKey: () => ({ // [!code ++]
    expiry: '1d', // [!code ++]
    limits: [{ limit: '100', token: 'ousd' }], // [!code ++]

  chain: 'testnet', // [!code ++]
  plugins: [dialog(), mpp(), viem()], // [!code ++]
}) // [!code ++]
```

## Errors

`ExecutionError` moves to `viem/tempo`, and `ExecutionError.from` replaces `ExecutionError.parse`.

```ts [parse.ts]
import { ExecutionError } from 'accounts' // [!code --]
import { ExecutionError } from 'viem/tempo' // [!code ++]

export function parse(error: Error) {
  const parsed = ExecutionError.parse(error) // [!code --]
  const parsed = ExecutionError.from(error) // [!code ++]
  return parsed
}
```

Version 0's provider rejects with an RPC error and its code. An instance throws named errors:

| Version 1                                                                                                       | Condition                                                                                                                           |
| --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| <SourceLink name="RequestError" path="src/Accounts.ts">`Accounts.RequestError`</SourceLink>                     | Tempo ID refuses a request. Its <SourceLink name="RequestError.reason" path="src/Accounts.ts">`reason`</SourceLink> names the cause |
| <SourceLink name="AccessKeyRequiredError" path="src/Accounts.ts">`Accounts.AccessKeyRequiredError`</SourceLink> | The session holds no access key for the call                                                                                        |
| <SourceLink name="SignedOutError" path="src/Accounts.ts">`Accounts.SignedOutError`</SourceLink>                 | A Viem action runs while the instance holds no session                                                                              |

## Removed APIs

Version 1 has no replacement for these APIs.

| Version 0                                                    | Reason                                                                                                                   |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| `local`, `secp256k1`, `turnkey`, `webAuthn`, `privy`         | An instance holds no owner key                                                                                           |
| `Adapter`                                                    | A plugin of <SourceLink name="from" path="src/Plugin.ts">`Plugin.from`</SourceLink> extends an instance                  |
| `Remote`, `Dialog`, `Messenger`, `Mount`, `postMessage`      | Tempo ID is the only wallet side                                                                                         |
| `Handoff`, `handoff`                                         | Version 1 has no phone handoff                                                                                           |
| `IntersectionObserver`                                       | The <SourceLink name="dialog" path="src/plugins/dialog.ts">`dialog`</SourceLink> plugin reads the support of the browser |
| `Keystore`, `accessKey.keystores`                            | The instance creates and keeps the access key                                                                            |
| `Schema`, `Rpc`, `ProviderRequest`, `wallet_getCapabilities` | The instance serves no RPC request                                                                                       |
| `Handler.codeAuth`, `Handler.deviceCode`, `CliAuth`          | Tempo ID serves the device grant                                                                                         |
| `Handler.webAuthn`, `WebAuthnCeremony`                       | Tempo ID runs each passkey ceremony                                                                                      |
| `Handler.oidcProvider`, `Identity`, `identity`               | Tempo ID issues each token, with the verified <SourceLink name="Session.user" path="src/Session.ts">`user`</SourceLink>  |
| `Handler.exchange`                                           | The page reads each quote through <SourceLink name="viem" path="src/plugins/viem.ts">`accounts.dex`</SourceLink>         |
| `hc`                                                         | `hono/client` exports it                                                                                                 |
| `Mach.getFundingUrl`                                         | <SourceLink name="open" path="src/plugins/funding.ts">`accounts.funding.open()`</SourceLink> opens the deposit page      |
| `icon`, `name`, `rdns`, `theme`                              | Tempo ID's approval page names the app, and takes no theme                                                               |
| `cacheTtl`, `kv` of `Handler.relay`                          | The <SourceLink name="relay" path="src/plugins/relay.ts">`relay`</SourceLink> plugin holds no cache                      |
