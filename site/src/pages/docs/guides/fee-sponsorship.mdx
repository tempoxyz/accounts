# Fee Sponsorship

Sponsor transaction fees for connected accounts without moving sponsorship policy into your client. Your app runs a relay with `Handler.relay`, the connector routes wallet RPC through that relay, and each sponsored request can still opt out of fee sponsorship.

The runnable [Fee Payer example](https://github.com/tempoxyz/accounts/tree/main/examples/fee-payer) shows the full shape with Tempo Wallet, a Cloudflare Worker relay, and a sponsored pathUSD transfer. The same pattern is available with domain-bound passkeys in the [Fee Payer + WebAuthn example](https://github.com/tempoxyz/accounts/tree/main/examples/fee-payer-and-webauthn).

## Demo

By the end of this guide you'll have the same fee sponsorship pattern as the Fee Payer example: the user signs in, your server decides whether to sponsor a request, and matching transfers can be routed through the server-owned fee payer.

## Walkthrough

::::steps

### Connect an Account

Follow the [Connect Accounts](/docs/guides/connect-accounts) guide to set up Wagmi with Tempo Wallet, WebAuthn, or another signing adapter. Fee sponsorship works after the user has a connected account that can sign the transaction.

### Install the Server Dependencies

Install the Accounts SDK with Wagmi, Viem, and a server framework. This guide uses [Hono](https://hono.dev), matching the Fee Payer example.

:::code-group

```bash [npm]
npm i accounts wagmi viem hono
```

```bash [pnpm]
pnpm i accounts wagmi viem hono
```

```bash [bun]
bun i accounts wagmi viem hono
```

:::

### Mount the Relay

Create a [`Handler.relay`](/docs/server/handler.relay) with a `feePayer` account and expose it under `/relay`. The relay fills incoming transactions, signs the fee payer portion when sponsorship is approved, and returns a transaction that the connected account can sign.

```ts twoslash [worker/index.ts]
// @noErrors
import { Handler } from 'accounts/server'
import { Hono } from 'hono'
import { privateKeyToAccount } from 'viem/accounts'

const app = new Hono()

app.all('/relay/*', (c) =>
  Handler.relay({
    feePayer: {
      account: privateKeyToAccount(process.env.RELAY_PRIVATE_KEY),
      name: 'My App',
      url: 'https://myapp.com',
    },
    path: '/relay',
  }).fetch(c.req.raw),
)

export default app
```

:::warning[Add a sponsorship policy]
The minimal example sponsors any transaction sent to the relay. Before funding a production fee payer account, add `feePayer.validate`, rate limits, and logging so your server only sponsors the requests your app intends to support.
:::

### Configure the Connector

Pass the relay URL to your connector with `relay`. In development, the Fee Payer example uses a Cloudflare Tunnel so the Tempo Wallet iframe can reach your local relay. In production, use the HTTPS URL of your deployed relay.

:::tip[Keep transports on the relay]
If you configure Wagmi `transports`, point them at the relay's per-chain URLs. Plain `http()` transports are also forwarded to the Accounts Provider, where they override the relay-generated transports.
:::

:::code-group

```tsx twoslash [Tempo Wallet]
// @noErrors
import { createConfig, http } from 'wagmi'
import { tempo, tempoModerato } from 'wagmi/chains'
import { tempoWallet } from 'wagmi/connectors'

const relay = import.meta.env.VITE_RELAY_URL ?? '/relay'

export const config = createConfig({
  chains: [tempo, tempoModerato],
  connectors: [
    tempoWallet({
      testnet: true,
      relay, // [!code focus]
    }),
  ],
  multiInjectedProviderDiscovery: false,
  transports: {
    [tempo.id]: http(`/relay/${tempo.id}`), // [!code focus]
    [tempoModerato.id]: http(`/relay/${tempoModerato.id}`), // [!code focus]
  },
})
```

```tsx twoslash [Domain-bound Passkeys]
// @noErrors
import { createConfig, http } from 'wagmi'
import { tempo, tempoModerato } from 'wagmi/chains'
import { webAuthn } from 'wagmi/tempo'

const relay = '/relay'

export const config = createConfig({
  chains: [tempo, tempoModerato],
  connectors: [
    webAuthn({
      testnet: true,
      authUrl: '/auth',
      relay, // [!code focus]
    }),
  ],
  multiInjectedProviderDiscovery: false,
  transports: {
    [tempo.id]: http(`/relay/${tempo.id}`), // [!code focus]
    [tempoModerato.id]: http(`/relay/${tempoModerato.id}`), // [!code focus]
  },
})
```

:::

### Send a Transfer

Call [`Hooks.wallet.useTransfer`](https://wagmi.sh/tempo/hooks/wallet.useTransfer) normally. With `relay` configured, the transfer routes through your relay by default, where the server decides whether to sponsor it.

```tsx twoslash [Transfer.tsx]
// @noErrors
import { Hooks } from 'wagmi/tempo'

export function Transfer() {
  const transfer = Hooks.wallet.useTransfer()

  return (
    <button
      disabled={transfer.isPending}
      onClick={() =>
        transfer.mutate({
          amount: '1',
          to: '0x0000000000000000000000000000000000000001',
          token: 'pathusd',
        })
      }
    >
      {transfer.isPending ? 'Sending...' : 'Pay $1'}
    </button>
  )
}
```

### Show the Fee Payer

The transfer result includes the submitted receipt. When sponsorship succeeds, `receipt.feePayer` is the server-owned account that paid the transaction fee.

```tsx twoslash [Transfer.tsx]
// @noErrors
import { Hooks } from 'wagmi/tempo'

export function Transfer() {
  const transfer = Hooks.wallet.useTransfer()

  return (
    <div>
      <button onClick={() => transfer.mutate({ /* ... */ })}>Pay $1</button>
      {transfer.data?.receipt.feePayer && (
        <p>
          Fees paid by <code>{transfer.data.receipt.feePayer}</code>
        </p>
      )}
    </div>
  )
}
```

:::tip[Per-request control]
The transfer above does not pass a `feePayer` override. With `relay`, requests route through your relay and the relay sponsors them when `Handler.relay` has a `feePayer` configured. Only pass `feePayer: false` when you intentionally want the connected account to pay its own transaction fee.
:::

::::

## Best Practices

### Validate Sponsorship Server-Side

Treat the relay as the policy boundary. Use `feePayer.validate` to check the account, target contracts, calldata, token amounts, and any app-level limits before signing. Returning `false` does not reject the transaction outright — the relay re-fills it for self-payment.

```ts twoslash [worker/index.ts]
// @noErrors
import { Handler } from 'accounts/server'
import { privateKeyToAccount } from 'viem/accounts'

const blocked = '0x0000000000000000000000000000000000000001'

const handler = Handler.relay({
  feePayer: {
    account: privateKeyToAccount('0x...'),
    validate: (request) =>
      request.from?.toLowerCase() !== blocked.toLowerCase(), // [!code focus]
  },
})
```

### Keep the Fee Payer Reachable

Tempo Wallet runs outside your app origin, so local private-network endpoints are not always reachable from the embedded approval flow. Use the tunnel setup from `examples/fee-payer` during development, and use a stable HTTPS relay URL in deployed environments.

### Limit the Fee Payer Account

Fund the fee payer account with only the amount and fee token required for the workflow. Rotate the private key if it is exposed, and keep it in your server secret store rather than browser-readable environment variables.

### Log Decisions

Log sponsorship approvals and rejections with account, chain, requested calls, and validation reason. Do not log private keys, raw signatures, session cookies, or other secret material.
