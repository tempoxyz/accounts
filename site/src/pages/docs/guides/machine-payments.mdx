# Machine Payments (MPP)

## Outcome

Build machine payment flows where services can request payment with HTTP `402` and clients can return payment proof in the same request lifecycle.

## Demo

:::info[Phase 2 demo]
This section will become an interactive demo in Phase 2.
:::

| Item | Value |
| --- | --- |
| Final interaction | Request a protected resource, receive an HTTP `402` Challenge, pay, retry with a Credential, and receive a Receipt. |
| Target workspace | `examples/machine-payments/`. |
| Success state | The client receives the resource and stores the Receipt proving the payment was accepted. |
| Implementation owner surface | Machine flows usually use stored account permission or server-owned UI. Any human approval step is owned by the selected adapter. |

## Prerequisites

- A service that can return an HTTP `402` Challenge.
- A client account, access key, or server signer that can satisfy the Challenge.
- A reconciliation path for Credential and Receipt records.

## Setup

Install the SDK packages.

```bash
pnpm add accounts mppx viem
```

Choose the account adapter that signs machine payment requests.

Use Tempo Wallet when a human should approve the initial account or permission. Use WebAuthn or a custom adapter when your app owns that approval UI. Use an access key when a service needs to pay repeatedly without prompting a human for every request.

## Implementation

Load the account or access key used by the machine actor.

Request the protected resource. If the service requires payment, it returns an HTTP `402` Challenge. The client pays using a supported method and retries with a Credential.

## Verification

The service verifies the Credential, returns the resource, and includes a Receipt. Persist the Receipt with the request metadata so the client can reconcile what was paid for.

## Production notes

- MPP defines the payment negotiation and proof flow; Tempo provides stablecoin settlement and session payments.
- Do not imply every MPP payment requires Tempo. Tempo is the preferred settlement path for Tempo-native stablecoin flows.
- Separate human approval from machine payment execution. Use spend permissions when repeat payment should happen without a prompt.
- Log Challenge, Credential, and Receipt identifiers for reconciliation.
