# Payments

## Outcome

Send a stablecoin payment from a connected account and show the receipt that proves the payment settled.

## Demo

:::info[Phase 2 demo]
This section will become an interactive demo in Phase 2.
:::

| Item | Value |
| --- | --- |
| Final interaction | Connect an account, fund it if needed, send a small stablecoin payment, and display the receipt. |
| Target workspace | `examples/payments/`. |
| Success state | The app shows the transaction receipt, token amount, recipient, and refreshed balance. |
| Implementation owner surface | Tempo Wallet uses hosted approval UI. WebAuthn and custom adapters use app-owned approval UI. |

## Prerequisites

- A connected account from [Connect Accounts](/docs/guides/connect-accounts).
- A stablecoin token address, decimals, and recipient address for the target environment.
- Enough balance for the transfer and fee, unless the app uses fee sponsorship.

## Setup

Install the SDK packages.

```bash
pnpm add accounts wagmi viem
```

Use the same Wagmi configuration from [Connect Accounts](/docs/guides/connect-accounts).

Connect through Tempo Wallet, WebAuthn, or a custom adapter.

## Implementation

Use Tempo actions or hooks to submit the transfer.

```tsx
import { parseUnits } from 'viem'
import { Actions } from 'viem/tempo'
import { useSendTransactionSync } from 'wagmi'

const pathUsd = '0x20c0000000000000000000000000000000000000'

function Pay() {
  const { sendTransactionSync } = useSendTransactionSync()

  return (
    <button
      onClick={() =>
        sendTransactionSync({
          calls: [
            Actions.token.transfer.call({
              token: pathUsd,
              to: '0x0000000000000000000000000000000000000001',
              amount: parseUnits('1', 6),
            }),
          ],
        })
      }
    >
      Pay
    </button>
  )
}
```

## Verification

Show the returned receipt and refresh the account balance. The receipt should be enough for the app to show the amount, token, recipient, chain, and transaction status without asking the user to inspect a block explorer.

## Production notes

- Keep the token address, decimals, and display symbol in app configuration instead of scattering literals across components.
- Show insufficient-balance states before opening an approval surface.
- Pair this guide with [Fee Sponsorship](/docs/guides/fee-sponsorship) when the app pays network fees for the user.
- For WebAuthn and custom adapters, design the payment confirmation UI. The SDK provides the provider surface, not hosted UI.
