# React Native

React Native apps can connect to Tempo Wallet with mobile web auth. The provider opens Tempo Wallet in a system browser session, then receives an app-link callback with the encrypted response.
Each mobile web auth request is a single exchange: one browser auth URL carries one RPC request, and one callback URL carries one RPC response.

```ts twoslash
import { Provider } from 'accounts'
import { tempoWallet } from 'accounts/mobileWebAuth/tempoWallet'
import { openAuthSession } from 'accounts/react-native/expo-web-browser'

const redirectUri = 'com.example.app:/auth'

const provider = Provider.create({
  adapter: tempoWallet({ openAuthSession, redirectUri }),
})
```

`accounts/react-native/expo-web-browser` uses Expo WebBrowser for the native
system auth session. It is an optional React Native subpath so apps that use
another browser primitive do not install Expo WebBrowser.

## Consumer Discovery

The mobile web auth `tempoWallet()` adapter uses `https://wallet.tempo.xyz` for both discovery origins by default:

- `baseUrl`: consumer discovery origin serving `/.well-known/urpc/consumer.json`
- `host`: wallet discovery origin serving `/.well-known/urpc/host.json`

Using the same origin is valid when the mobile app and wallet are owned by the same domain. The consumer document must include the exact `redirectUri` passed to `tempoWallet()`.

```json
{
  "callback_urls": [
    "xyz.tempo.accounts.playground:/auth",
    "xyz.tempo.accounts.playground://auth"
  ],
  "id": "wallet.tempo.xyz",
  "name": "Tempo Wallet",
  "origin": "https://wallet.tempo.xyz",
  "version": "1.0"
}
```

Use a development build with a reverse-DNS private-use callback URI. Expo Go-style callback URLs are not valid mobile web auth callbacks. Publish the exact callback URI you pass to `tempoWallet()` in the consumer document.

## Custom Wallet Hosts

Use `mobileWebAuth()` directly when the app origin, wallet host, or provider identity differs from Tempo Wallet.

```ts twoslash
import { Provider } from 'accounts'
import { mobileWebAuth } from 'accounts/mobileWebAuth'
import { openAuthSession } from 'accounts/react-native/expo-web-browser'

const redirectUri = 'com.example.app:/auth'

const provider = Provider.create({
  adapter: mobileWebAuth({
    baseUrl: 'https://app.example',
    host: 'https://wallet.example',
    name: 'Example Wallet',
    openAuthSession,
    rdns: 'com.example.wallet',
    redirectUri,
  }),
})
```

## Options

### tempoWallet

`tempoWallet()` accepts `redirectUri`, `openAuthSession`, and optional `fetch`. It uses Tempo Wallet metadata and discovery origins.

### mobileWebAuth

`mobileWebAuth()` is the lower-level mobile web auth adapter. It requires `baseUrl`, `host`, `name`, `openAuthSession`, `rdns`, and `redirectUri` so custom integrations do not inherit Tempo Wallet metadata accidentally.

### baseUrl

- **Type:** `string`
- **Required by:** `mobileWebAuth()`

Public origin serving the consumer discovery document.

### redirectUri

- **Type:** `string`
- **Required**

Deep-link URI watched by the system browser auth session.

### name

- **Type:** `string`
- **Required by:** `mobileWebAuth()`

Display name sent to Tempo Wallet during mobile web auth.

### rdns

- **Type:** `string`
- **Required by:** `mobileWebAuth()`

Reverse-DNS app identifier sent to Tempo Wallet during mobile web auth.

### host

- **Type:** `string | HostDocument`
- **Required by:** `mobileWebAuth()`

Tempo Wallet discovery origin, or a preloaded host document.

### openAuthSession

- **Type:** `({ authorizationUrl, callback }) => string | undefined | Promise<string | undefined>`
- **Required**

Browser auth-session primitive. Use `accounts/react-native/expo-web-browser` for Expo apps, or pass the equivalent native auth-session integration for another platform.
