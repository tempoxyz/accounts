# React Native

React Native apps connect to a wallet through [mobile web auth](/docs/api/mobileWebAuth): the provider opens the wallet in a system browser session, then receives an app-link callback with the encrypted response.

This guide covers the platform setup. For choosing and configuring the adapter itself, see the [Tempo Wallet adapter](/docs/adapters/tempo-wallet) or the [mobileWebAuth reference](/docs/api/mobileWebAuth).

## Install

```sh
npx expo install expo-web-browser expo-secure-store react-native-get-random-values react-native-mmkv react-native-nitro-modules
```

## Connect

```ts twoslash
import { Provider } from 'accounts'
import { tempoWallet } from 'accounts/mobileWebAuth'
import { openAuthSession } from 'accounts/react-native/expo-web-browser'
import { secureMmkv } from 'accounts/react-native/secure-mmkv'

const provider = Provider.create({
  adapter: tempoWallet({
    baseUrl: 'https://app.example',
    openAuthSession,
    redirectUri: 'com.example.app:/auth',
  }),
  storage: secureMmkv(),
})
```

## Development Builds

Use a development build with a reverse-DNS private-use callback URI (e.g. `com.example.app:/auth`). Expo Go-style callback URLs are not valid mobile web auth callbacks. The exact callback URI must be published in your app's [consumer discovery document](/docs/api/mobileWebAuth#consumer-discovery).

```sh
expo run:ios
```

## Polyfills

Import polyfills before the SDK so module-scope code finds them:

```js
// index.js
import './polyfills'
```

```js
// polyfills.js
import 'react-native-get-random-values'

if (typeof globalThis.MessageEvent === 'undefined') {
  globalThis.MessageEvent = class MessageEvent {
    constructor(type, options = {}) {
      this.data = options.data ?? null
      this.origin = options.origin ?? ''
      this.type = type
    }
  }
}
```

`react-native-get-random-values` provides `crypto.getRandomValues` for key generation. Hermes does not provide `MessageEvent`, which the SDK references at module scope.

## Browser Sessions

`accounts/react-native/expo-web-browser` opens auth sessions with Expo WebBrowser. It is an optional subpath so apps that use another browser primitive do not install Expo WebBrowser — pass your own `openAuthSession` that opens the authorization URL and resolves with the callback URL instead.

```ts twoslash
import { openAuthSession } from 'accounts/react-native/expo-web-browser'
```

## Storage

Provider state persists through a storage adapter. React Native adapters ship as optional subpaths:

```ts twoslash
import { asyncStorage } from 'accounts/react-native/async-storage'
import { getOrCreateMmkvEncryptionKey } from 'accounts/react-native/expo-secure-store'
import { secureMmkv } from 'accounts/react-native/secure-mmkv'
```

Use `secureMmkv` when the provider manages access keys. It stores the larger SDK snapshot in encrypted MMKV and keeps only the small encryption key in the device Keychain/Keystore through `getOrCreateMmkvEncryptionKey`.
