# User session [A session holds the user, the tokens, and the access key of a sign-in.]

## Overview

A sign-in returns a session, which holds the user, the tokens, and the [access key](/docs/guides/access-keys) of the sign-in. The instance saves it to its store, so a later load of the app restores it with no new sign-in.

With <SourceLink name="Config.guest" path="src/Accounts.ts">`guest`</SourceLink>, a sign-in can also return a [guest session](/docs/guides/guest-checkout), which holds no user and no tokens. <SourceLink name="guest" path="src/Session.ts">`Session.guest`</SourceLink> and <SourceLink name="tempoId" path="src/Session.ts">`Session.tempoId`</SourceLink> tell the kinds apart.

Each app that signs users in holds a session. Its access token lets the app call its own API as the user, which [verifies the token](/docs/guides/api-authentication/authenticate-requests).
