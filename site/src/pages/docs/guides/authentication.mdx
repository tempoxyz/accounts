# Authentication

## Outcome

Register a user, authenticate future sessions, and route account requests through the selected adapter.

## Demo

:::info[Phase 2 demo]
This section will become an interactive demo in Phase 2.
:::

| Item | Value |
| --- | --- |
| Final interaction | Register a domain-bound passkey account, sign out, and sign back in. |
| Target workspace | `examples/authentication/`, seeded from `examples/domain-bound-webauthn/`. |
| Success state | The app shows the authenticated account and the server can read session state. |
| Implementation owner surface | WebAuthn is bring-your-own UI: the app owns registration, sign-in, recovery, errors, and empty states. |

## Prerequisites

- A React app configured with Wagmi.
- A WebAuthn-capable browser and secure origin for realistic passkey testing.
- A server route for `Handler.webAuthn` or a custom `WebAuthnCeremony`.

## Setup

Install the SDK packages.

```bash
pnpm add accounts wagmi viem
```

Start with `webAuthn` when the app owns the passkey ceremony and account UI.

```tsx
import { createConfig, http } from 'wagmi'
import { tempo } from 'wagmi/chains'
import { webAuthn } from 'wagmi/tempo'

export const config = createConfig({
  chains: [tempo],
  connectors: [webAuthn({ authUrl: '/auth' })],
  transports: {
    [tempo.id]: http(),
  },
})
```

Pair the connector with `Handler.webAuthn` on the server. The handler owns challenge generation, verification, credential persistence, and optional session issuance.

## Implementation

Call `connect` with the registration capability when creating the passkey-backed account.

```tsx
connect({
  connector,
  capabilities: { method: 'register', name: 'My Wallet' },
})
```

Call `connect` with the same connector and let the adapter run the authentication ceremony.

Your app should render the sign-in, passkey prompt trigger, loading state, cancellation state, and recovery path. The Accounts SDK routes the account request after the ceremony succeeds; it does not provide hosted UI for WebAuthn.

## Verification

Read the connected account and confirm server-side session state if your adapter creates one.

## Production notes

- WebAuthn is origin-bound. Local examples need a secure origin when testing browser passkeys.
- Store challenges and credentials server-side through a durable `Kv` implementation in production.
- Decide what account recovery means before launch. Domain-bound passkeys cannot rely on Tempo Wallet recovery UI.
- Custom auth-backed adapters need a concrete session, signer boundary, approval UI, and error model.
