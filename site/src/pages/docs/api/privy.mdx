# `privy`

Creates a Privy adapter for Privy-authenticated embedded Ethereum wallets.

React apps should usually use `privyReact` from `accounts/react/privy`. It wraps this core adapter, opens Privy's login UI through a React boundary, and returns account objects with a raw signer and matching public key. When an account includes `publicKey`, the adapter builds a full Tempo viem account with `viem/tempo` `Account.from(...)`.

Use this core `privy` adapter directly for `@privy-io/js-sdk-core` integrations or custom React flows that need explicit account selection.

## Usage

```ts
import { Provider } from 'accounts'
import { privyReact } from 'accounts/react/privy'

export const provider = Provider.create({
  adapter: privyReact(),
})
```

The helper expects `PrivyAccountsBridge` under `PrivyProvider`:

```tsx
import { PrivyProvider } from '@privy-io/react-auth'
import { PrivyAccountsBridge } from 'accounts/react/privy'

root.render(
  <PrivyProvider appId={appId}>
    <PrivyAccountsBridge />
    <App />
  </PrivyProvider>,
)
```

The bridge resolves connect requests with Privy's viem accounts and matching public keys.

## Parameters

### client

- **Type:** `privy.Client`
- **Required**

Structural Privy client used by the core adapter. `Privy` from `@privy-io/js-sdk-core` satisfies this directly. React apps should prefer `privyReact()` unless they need a custom bridge.

The adapter calls `initialize?.()` once on first use, and uses `getAccessToken`, `user.get`, `embeddedWallet.getEthereumProvider`, and `auth.logout` for the rest of the lifecycle.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client, // [!code focus]
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
  }),
})
```

### icon

- **Type:** `` `data:image/${string}` ``
- **Optional**

Data URI of the provider icon.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
    icon: 'data:image/svg+xml,...', // [!code focus]
  }),
})
```

### loadAccounts

- **Type:** `(params: { client; parameters? }) => Promise<privy.AccountSelection>`
- **Required**

Runs the Privy login UI in response to a user-initiated `wallet_connect`.

For React apps using `privyReact()`, this callback is supplied by the SDK. Custom integrations can still use a bridge component to open Privy's login modal and return the `toViemAccount({ wallet })` results with the matching wallet public key. The first returned account is active by default, matching `eth_requestAccounts`.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    }, // [!code focus]
  }),
})
```

For Core JS integrations, the callback may run auth and return no value. After it completes, the adapter loads embedded Ethereum wallets from Privy SDK state with `client.user.get()` and `client.embeddedWallet.getEthereumProvider(...)`.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
  }),
})
```

### createAccount

- **Type:** `(params: { client; parameters }) => Promise<privy.AccountSelection>`
- **Optional**
- **Default:** `loadAccounts`

Runs a distinct Privy registration flow when registration needs to differ from login. The callback receives the initialized Privy `client` and the provider create-account `parameters` (display name, optional `digest`, `personalSign`, `userId`, etc.).

Like `loadAccounts`, React integrations can return materialized Privy viem accounts, and Core JS integrations can return addresses or no value.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    createAccount: async ({ client }) => {
      await registerWithPrivy(client.auth)
    }, // [!code focus]
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
  }),
})
```

### name

- **Type:** `string`
- **Default:** `'Privy'`

Display name of the provider.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
    name: 'My Wallet', // [!code focus]
  }),

```

### rdns

- **Type:** `string`
- **Default:** `'io.privy'`

Reverse DNS identifier.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async ({ client }) => {
      await signInWithPrivyEmail(client.auth)
    },
    rdns: 'com.example.wallet', // [!code focus]
  }),
})
```

## AccountSelection

- **Type:** `readonly (Address | privy.Account)[] | void`

Optional selection returned from a Privy login or sign-up callback. When omitted, all embedded Ethereum wallets loaded from Privy are used. When provided, the returned values select and order the accounts exposed through the provider.

Return `privy.Account` objects when you can, especially accounts assembled from `@privy-io/react-auth` `toViemAccount({ wallet })` plus the wallet public key. Return addresses only when your integration cannot expose a public key.

```ts
import { toViemAccount } from '@privy-io/react-auth'

const selection = await Promise.all(
  wallets.map(async (wallet) => {
    const account = await toViemAccount({ wallet })
    const publicKey = getPublicKey(privy.user, wallet.address)
    return { ...account, ...(publicKey ? { publicKey } : {}) }
  }),
)
```

## Account Shape

`privy.Account` is structural so apps can pass Privy's React SDK account without this package depending on `@privy-io/react-auth`.

```ts
import { privy } from 'accounts'

type Account = {
  address: string
  publicKey?: string | undefined
  sign?: ((parameters: { hash: `0x${string}` }) => Promise<`0x${string}`>) | undefined
}
```

When `publicKey` is present, the adapter validates that it matches `address` and builds a full Tempo account. The optional `sign` function is used with that public key. When only `address` is returned, the adapter uses the embedded provider fallback.

## Client Shape

`privy.Client` is structural. `Privy` from `@privy-io/js-sdk-core` satisfies this directly. React apps should prefer `privyReact()` unless they need to customize the bridge.

```ts
import { privy } from 'accounts'

type Client = {
  auth: {
    logout: (parameters?: { userId: string } | undefined) => Promise<void> | void
  }
  embeddedWallet: {
    getEthereumProvider(parameters: {
      wallet: privy.LinkedAccount
      entropyId: string
      entropyIdVerifier: string
    }): Promise<privy.EthereumProvider> | privy.EthereumProvider
  }
  getAccessToken: () => Promise<string | null>
  initialize?: (() => Promise<void> | void) | undefined
  user: {
    get: () => Promise<{ user: privy.User }>
  }
}
```
