# Privy Adapter

The Privy adapter is for apps that want Privy to own authentication, session state, and embedded wallets while plugging into Tempo account features. Prefer `@privy-io/react-auth` for React apps because Privy's hooks can provide the wallet public key and raw signer the adapter needs to build a full Tempo viem account.

Use it when you want:

- Privy to own app authentication and embedded wallets.
- Your React app to keep using Privy's hosted login UI.
- Tempo account features backed by a full viem account whenever Privy exposes the public key.

## Usage

Wrap your app with `PrivyProvider`, configure embedded Ethereum wallet creation, and mount a small bridge component that resolves Accounts SDK connect requests with Privy's `toViemAccount({ wallet })` result plus the matching wallet public key.

:::code-group

```tsx [main.tsx]
import { PrivyProvider } from '@privy-io/react-auth'
import { createRoot } from 'react-dom/client'

import { App } from './App.js'
import { PrivyAccountsBridge } from './PrivyAccountsBridge.js'

createRoot(document.getElementById('root')!).render(
  <PrivyProvider
    appId={import.meta.env.VITE_PRIVY_APP_ID}
    config={{
      embeddedWallets: {
        ethereum: { createOnLogin: 'users-without-wallets' },
      },
    }}
  >
    <PrivyAccountsBridge />
    <App />
  </PrivyProvider>,
)
```

```ts [provider.ts]
import { Provider, privy } from 'accounts'

import {
  privyReactClient,
  requestPrivyAccounts,
} from './privy-react-bridge.js'

export const provider = Provider.create({
  adapter: privy({
    client: privyReactClient,
    loadAccounts: async () => await requestPrivyAccounts(),
  }),
})
```

```tsx [PrivyAccountsBridge.tsx]
import { type User, toViemAccount, useLogin, usePrivy, useWallets } from '@privy-io/react-auth'
import { useEffect, useRef } from 'react'

import {
  rejectPrivyAccounts,
  resolvePrivyAccounts,
  syncPrivyReactState,
  usePrivyAccountsRequest,
} from './privy-react-bridge.js'

export function PrivyAccountsBridge() {
  const privy = usePrivy()
  const wallets = useWallets()
  const request = usePrivyAccountsRequest()
  const pending = useRef(false)
  const login_started = useRef(false)
  const login = useLogin({
    onError(error) {
      login_started.current = false
      rejectPrivyAccounts(new Error(String(error)))
    },
  })

  useEffect(() => {
    syncPrivyReactState({ privy, wallets })
  }, [privy, wallets])

  useEffect(() => {
    if (!request || pending.current || !privy.ready) return

    if (!privy.authenticated) {
      if (!login_started.current) {
        login_started.current = true
        login.login()
      }
      return
    }

    login_started.current = false
    if (!wallets.ready) return

    pending.current = true
    void (async () => {
      try {
        const embedded = wallets.wallets.filter(
          (wallet) =>
            wallet.type === 'ethereum' &&
            (wallet.walletClientType === 'privy' ||
              wallet.walletClientType === 'privy-v2'),
        )
        resolvePrivyAccounts(
          await Promise.all(
            embedded.map(async (wallet) => {
              const account = await toViemAccount({ wallet })
              const publicKey = getPublicKey(privy.user, wallet.address)
              return { ...account, ...(publicKey ? { publicKey } : {}) }
            }),
          ),
        )
      } catch (error) {
        rejectPrivyAccounts(error instanceof Error ? error : new Error(String(error)))
      } finally {
        pending.current = false
      }
    })()
  }, [login, privy.authenticated, privy.ready, request, wallets.ready, wallets.wallets])

  return null
}

function getPublicKey(user: User | null | undefined, address: string) {
  return user?.linkedAccounts.find(
    (account) =>
      account.type === 'wallet' &&
      account.chainType === 'ethereum' &&
      account.address.toLowerCase() === address.toLowerCase(),
  )?.publicKey
}
```

## Account Selection

By default, all embedded Ethereum wallets on the Privy user are connected. Return addresses from `createAccount` or `loadAccounts` only when you want to select or order the accounts exposed through the provider.

```ts
const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async () => [selectedAddress],
  }),
})
```

React integrations should return account objects with a public key and raw signer instead of only returning addresses when possible. Privy's `toViemAccount({ wallet })` provides the raw signer, and the wallet public key can be read from Privy's authenticated user state.

```ts
import { toViemAccount } from '@privy-io/react-auth'

const accounts = await Promise.all(
  wallets.map(async (wallet) => {
    const account = await toViemAccount({ wallet })
    const publicKey = getPublicKey(privy.user, wallet.address)
    return { ...account, ...(publicKey ? { publicKey } : {}) }
  }),
)
```

The first returned address or account is active by default.

## Core JS Fallback

The adapter still supports a structural client compatible with `@privy-io/js-sdk-core`. This path is useful outside React or for apps that already own a Core JS integration. Core JS embedded Ethereum wallet records do not currently expose a public key in the linked-account shape, so address-only callbacks use the adapter's provider signing fallback through `secp256k1_sign`.
