# Privy Adapter

The Privy adapter is for apps that want Privy to own authentication, session state, and embedded wallets while plugging into Tempo account features. React apps should use `privyReact` from `accounts/react/privy`; it wires Privy's hooks into the core adapter and builds a full Tempo viem account when Privy exposes a public key.

Use it when you want:

- Privy to own app authentication and embedded wallets.
- Your React app to keep using Privy's hosted login UI.
- Tempo account features backed by a full viem account whenever Privy exposes the public key.

## Usage

Wrap your app with `PrivyProvider`, configure embedded Ethereum wallet creation, and mount `PrivyAccountsBridge` inside the same React tree. Then create the provider with `privyReact()`.

:::code-group

```tsx [main.tsx]
import { PrivyProvider } from '@privy-io/react-auth'
import { PrivyAccountsBridge } from 'accounts/react/privy'
import { createRoot } from 'react-dom/client'

import { App } from './App.js'

createRoot(document.getElementById('root')!).render(
  <PrivyProvider
    appId={import.meta.env.VITE_PRIVY_APP_ID}
    config={{
      embeddedWallets: {
        ethereum: { createOnLogin: 'users-without-wallets' },
      },
    }}
  >
    <PrivyAccountsBridge />
    <App />
  </PrivyProvider>,
)
```

```ts [provider.ts]
import { Provider } from 'accounts'
import { privyReact } from 'accounts/react/privy'

export const provider = Provider.create({
  adapter: privyReact(),
})
```

:::

:::tip
`PrivyAccountsBridge` is a React boundary. It exists because Privy's `usePrivy`, `useWallets`, and `useLogin` hooks can only run under `PrivyProvider`, while the Accounts SDK provider is plain TypeScript.
:::

## Account Selection

With `privyReact()`, all embedded Ethereum wallets on the Privy user are connected. Use the core `privy` adapter directly when you need to select or order the accounts exposed through the provider.

```ts
import { Provider, privy } from 'accounts'

const provider = Provider.create({
  adapter: privy({
    client,
    loadAccounts: async () => [selectedAddress],
  }),
})
```

Advanced React integrations should return account objects with a public key and raw signer instead of only returning addresses when possible. Privy's `toViemAccount({ wallet })` provides the raw signer, and the wallet public key can be read from Privy's authenticated user state.

```ts
import { toViemAccount } from '@privy-io/react-auth'

const accounts = await Promise.all(
  wallets.map(async (wallet) => {
    const account = await toViemAccount({ wallet })
    const publicKey = getPublicKey(privy.user, wallet.address)
    return { ...account, ...(publicKey ? { publicKey } : {}) }
  }),
)
```

The first returned address or account is active by default.

## Core JS Fallback

The adapter still supports a structural client compatible with `@privy-io/js-sdk-core`. This path is useful outside React or for apps that already own a Core JS integration. Core JS embedded Ethereum wallet records do not currently expose a public key in the linked-account shape, so address-only callbacks use the adapter's provider signing fallback through `secp256k1_sign`.
