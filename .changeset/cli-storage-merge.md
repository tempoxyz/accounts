`Storage.filesystem` merges each write into the file as it is on disk instead of replacing it, so a CLI process no longer undoes changes another process saved after it loaded the store. A write takes a cross-process lock on the file, re-reads it, and applies only the fields this process changed since it last read or wrote them. `accounts` and `accessKeys` merge per record, keyed by address (and by account and chain for access keys); a record another process removed stays removed. The active account follows its address, and `auth` follows the selected login. A disconnect or `accessKeys.clear()` replaces what it clears, a `wallet_connect` keeps the accounts it connects even over a concurrent logout, and `maxAccounts` still holds after a merge. When both processes change the same field or record, the later write wins it. A process that has no concurrent writer writes the same file contents as before. The file's directory must not be writable by every user or owned by another user. `wallet_disconnect` now fails if storage cannot save the cleared state, instead of reporting success while credentials remain stored.
